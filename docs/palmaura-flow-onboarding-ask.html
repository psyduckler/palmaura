Request contract

This is the shape the app/backend should converge toward if we ship the new ask screen. The important product rule: profile calibrates; session intent drives the answer.

Durable profile

  • birthDate: date of birth including year.
  • dominantHand: right / left / ambidextrous.
  • gender: user-provided identity/voice context.
  • Stored on-device and editable in Settings.

Session intent

  • focus: relationship / career / money / family / path / custom.
  • question: one short sentence for this reading.
  • Stored with reading history, not user profile.
  • Optional skip can fall back to focus-only.

Prompt rule

  • Start with a direct answer to the question.
  • Use palm lines as evidence, not decoration.
  • Use DOB/gender/hand softly; avoid hard predictions or identity claims.
  • Keep entertainment-only language intact.

System notes

This revised flow has one extra screen, but it should increase perceived specificity a lot. Worth the tap.

State model

  • Profile state: long-lived and editable in Settings.
  • Reading draft: focus/question + photo before generation.
  • Reading result: generated content + map + private full report. No share artifacts for now.

UX decision

  • The ask screen should precede capture, so the photo feels purposeful.
  • Question should be short; long journaling belongs elsewhere.
  • Skip is allowed, but default path should ask.

Open questions

  • Should custom question be required after selecting “custom”?
  • Should reading history show the full question or only the focus?
  • Should reading history group by focus area, date, or last-opened result?
