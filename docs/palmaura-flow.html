PalmAura · App Flow Review

Current native flow, mirrored in HTML.

This review board reflects the current merged iOS app on main: disclaimer/profile gates, persistent Home/Settings navigation, question-first readings, live camera-in-box capture with library fallback, clean palm-map lenses, saved reading history, text-first share-card export, and App Store-ready privacy/contact surfaces.

Source: psyduckler/palmaura · main Backend: https://palmaura.app/api/read Contact: hello@palmaura.app Static artifact · open locally · no external assets
Merge stack included

What changed since the old board

  • Home now has focus chips, returning-user “Past Readings,” and last-answer recap.
  • History store saves up to 25 readings with thumbnails, delete, and clear-all paths.
  • Full report exposes “Share this reading,” opening a 9:16 card preview sheet.
  • Share sheet supports system share and add-only Photos permission flow.
  • Settings now includes Keepsakes → Library of readings and hello@palmaura.app.
  • Project metadata includes photo add usage and non-exempt encryption declaration.

Implementation notes

Root gating

RootView plays splash once per launch, then gates disclaimer and profile before HomeView. Persistent nav routes Home/Settings through NavigationCoordinator.

Payload and storage

Reads send clientRequestId, deviceId, appVersion, locale, imageBase64Jpeg, and saved/session onboarding context to /api/read. Reading JSON, session intent, and palm photo are kept on-device.

History and migration

ReadingHistoryStore keeps newest-first readings, caps to 25, and only clears legacy data after the new store persists successfully. Library rows restore bundles for report/map reopening.

Share privacy

ShareCardView exports a 1080×1920 9:16 card from title, summary, aura, archetype, and domain. It intentionally omits the user's raw question.

App Store surface

Xcode metadata includes camera/photo usage, add-only Photos save flow, and non-exempt encryption declaration. Public contact is hello@palmaura.app.

Review focus

Next UX decision: whether question-first stays before capture every time or becomes an optional detail at review/loading. Current build favors explicit intent before scan.
